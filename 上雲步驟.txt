Bitunix 掃描器 → GitHub Actions 上雲步驟
========================================

【已完成可略過】
- repo: https://github.com/yens01/bitunix-scanner
- Secrets: TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID
- 工作流: .github/workflows/scan.yml（每 15 分鐘 schedule + 可手動）


【為什麼一直要手動？時間又變 +0？】
1) GitHub schedule 忙碌時會延遲或丟掉（尤其以前 */5）
2) 按「Re-run / 重新執行」只會重跑「當時那版程式」
   → 你的 #1 鎖在舊 commit，時間仍是 UTC(+0)
3) 正確做法：Actions → Bitunix Scan → 「Run workflow」開「新的一輪」
   → 才會用 main 最新碼（含台灣時間 +8）

自動成功：列表出現新 run，且寫 Scheduled（不是只重跑 #1）


【若 schedule 仍不跑：cron-job.org 外掛定時】
1) GitHub → Settings → Developer settings → Personal access tokens (classic)
   勾 repo、workflow，複製 token
2) https://cron-job.org 新增：
   URL:
   https://api.github.com/repos/yens01/bitunix-scanner/actions/workflows/scan.yml/dispatches
   Method: POST
   每 15 分鐘
   Header:
     Authorization: Bearer 你的TOKEN
     Accept: application/vnd.github+json
     Content-Type: application/json
   Body: {"ref":"main"}


【可選 Secrets（實盤風控；不設則用預設）】
- RISK_ACCOUNT_USDT＝帳戶資金（預設 1000）
- RISK_PCT_PER_R＝每筆風險%（預設 1＝固定 1R）
- RISK_MAX_SAME_SIDE＝同向未結上限（預設 2）
- RISK_MAX_TOTAL_OPEN＝總未結上限（預設 4）

【統計】
- 本機：python bitunix_scanner.py journal stats
  → YES v2 與「規劃 v2」分開勝率（規劃盤整：勝＝箱體成立）
- 雲端 watch-once：YES 與 BTC／ETH 日內規劃都會寫日記
  （排程：台 16:00／20:00／21:30 各記一輪；手機手動 plan 只推播、不算新日記）
- 手機「統計」：讀 cloud-journal，送今天的表格圖（開倉、平倉、進場、停損、止盈）。等回測進場標「計」，是計畫價（與本機 yes_journal.jsonl 不同檔）
- 雲端會 cache yes_journal.jsonl（與冷卻一齊），同向倉才跨次生效

【4H 大盤規劃】
- 盤整：短卡（箱體＋日／週／月偏向），不給假進出場
- 有方向且等回測：才展開完整計畫
- 同日內容不變：只推「無變化」短訊（cache session_plan_state.json）


【手機查幣】
- 對你的 Telegram Bot「幣看哨」傳：BTC / MAGIC / AVAXUSDT
- 會回類似 CMD detail 的摘要（含 4H／1H 結構 + 5m 進場窗）
- 要「立刻回」：雙擊 啟動Bot.bat（電腦開著跑 bot）
- 雲端排程：掃盤約每 15 分；若另設 Telegram Reply（每 30 秒）則手機查詢多半約 30～60 秒內回
- 真・立刻回：本機開 啟動Bot.bat
- 本機：python bitunix_scanner.py detail 幣種


【注意】
- 不要上傳 telegram.local.env
- Public：程式碼看得到，Secrets 仍保密
- 本機：啟動掃描.bat 或 python bitunix_scanner.py watch
